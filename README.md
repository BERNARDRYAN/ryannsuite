## Highlights

- **Fully static, $0 hosting.** A Next.js static export (`output: "export"`) on Cloudflare Pages, with
  no server runtime and no backend.
- **Fast and accessible.** Lighthouse scores 100 for performance, accessibility, best practices and
  SEO on mobile.
- **Strict security.**
  - Every page gets its own Content-Security-Policy, with SHA-256 hashes of its inline scripts
    (`scripts/add-csp.mjs`).
  - Security headers are set in `public/_headers`.
- **Content-driven.** All text and data live in `src/content/`. Adding an app is one object in
  `projects.ts`, and the home page, the case-study page, the sitemap and the structured data all
  pick it up.
- **Built for sharing and search:**
  - a generated share image for each app (`opengraph-image.tsx`),
  - JSON-LD for the person, the organisation and each app,
  - a sitemap and robots.txt.
- **Printable resume.** `/resume` prints to a clean one-page A4 PDF.
- **Light and dark themes** with no flash on load.
- **CI on every push:** GitHub Actions runs lint, type checking and the build.

**Stack:** Next.js 16 (App Router), React 19, TypeScript (strict), Tailwind CSS 4, Lucide React.

## Project layout

```
src/
  content/      ← all text, links and data (edit these)
    site.ts         brand, email, domain, socials, nav
    projects.ts     the apps in the suite
    experience.ts   work + education
    skills.ts       grouped skills
    changelog.ts    release notes for the suite and each app
  types/content.ts  types for the content files
  components/   ← render-only UI (ui/ primitives, layout/, sections/)
  app/          ← routes: /, /apps/[slug], /resume, /changelog, /privacy, /terms, /support, 404, sitemap, robots, manifest
public/         ← og.png, resume.pdf, _headers, _redirects, app screenshots
scripts/        ← postbuild steps: Windows export fix + per-page CSP (see NOTES.md)
.github/        ← CI: lint, typecheck and build on every push and PR
docs/           ← README screenshots (not deployed)
```

### Adding a new app

Add one object to the `projects` array in [`src/content/projects.ts`](src/content/projects.ts). Nothing else needs to change. The home grid, `/apps/<slug>/` page, sitemap, JSON-LD, support page and hero all pick it up.

- `accent` is one of `magenta | vermilion | ink | sky | orange | emerald | violet | rose | amber` (defined in `globals.css`).
- `logo` is the app's square icon in `public/projects/<slug>/`.
- `screenshots` are 16:9 WebP files in `public/projects/<slug>/`: a 1440px `screenshot-N.webp` and a 720px `screenshot-N-sm.webp` thumb. The first is the cover; also keep a `screenshot-1-sm.jpg`, which the share-image generator uses (it can't read WebP).
- Set `free: true` only if the app itself says it's free (it adds price 0 to structured data).

### Posting an update

Add an entry to [`src/content/changelog.ts`](src/content/changelog.ts), with `app` set to a project slug or `"suite"`. It appears on `/changelog/`, and app entries also show in that app page's "Recent updates" section.

### Adding a third-party script or service

Every page has a strict Content-Security-Policy, generated by `scripts/add-csp.mjs`. If you add analytics, embeds or API calls to another domain, add that origin to `script-src` / `connect-src` in that script, or the browser will block it.

## Local development

```bash
nvm use            # Node 24 (see .nvmrc)
npm install
npm run dev        # http://localhost:3000
npm run lint
npm run typecheck  # next typegen + tsc --noEmit
npm run build      # static export → out/ (postbuild then adds the CSP)
npm start          # serve out/ locally (npx serve out)
```

## Deploying to Cloudflare Pages ($0)

1. Push this repo to GitHub.
2. Open the Cloudflare dashboard, then go to **Workers & Pages → Create → Pages → Connect to Git** and pick the repo.
3. Build settings:
   - **Framework preset:** Next.js (Static HTML Export)
   - **Build command:** `npm run build`
   - **Build output directory:** `out`
   - **Environment variable:** `NODE_VERSION` = `24` (match `.nvmrc`)
4. Save and deploy. Every push to the production branch redeploys automatically.

**Alternative (direct upload, no Git):**

```bash
npm run build
npx wrangler pages deploy out --project-name ryannsuite
```

`public/_headers` (security headers + long cache for `/_next/static/*`) and `public/_redirects` are copied into `out/` and applied by Pages automatically.

## Custom domain

1. In Pages, go to **your project → Custom domains → Set up a custom domain**, enter the domain (e.g. `ryannsuite.com`) and follow the DNS steps. If the domain's DNS is already on Cloudflare, this is automatic.
2. Update `url` in [`src/content/site.ts`](src/content/site.ts). It drives `metadataBase`, canonical URLs, Open Graph URLs, `sitemap.xml` and `robots.txt`.
3. Optionally redirect the `*.pages.dev` address to the custom domain (see the example in `public/_redirects`), then rebuild and deploy.
